# DEC-20260903-001 — Learning Domain Model

- **Estado:** Accepted
- **Versión objetivo:** V0.1
- **Proyecto:** UAS Study Hub
- **Fecha:** 2026-09-03

## Tema

Definir el modelo de dominio mínimo del motor de aprendizaje antes de ampliar la implementación de UAS Study Hub.

## Decisión

Se mantiene `Course → Block → Topic` como estructura académica canónica.

Se incorporan las entidades de dominio:

- `Concept`
- `Skill`
- `LearningObjective`
- `LearningEvidence`
- `Mastery`
- `Recommendation`

El `Topic` continúa siendo la unidad principal de contenido y navegación. `Concept` y `Skill` no sustituyen al Topic: permiten representar qué debe comprender el estudiante y qué debe ser capaz de hacer. `LearningEvidence` registra por qué el sistema considera que existe aprendizaje.

El dominio no se obtiene por simple consumo de contenido. El `MasteryScore` se calcula a partir de evidencia explícita de estudio, active recall, quiz, repaso y aplicación.

## Motivo

La Master Specification v2 establece:

- progreso basado en evidencia;
- estados de dominio;
- un `Next Study Action` explicable;
- un Knowledge Graph;
- separación entre contenido académico y datos personales;
- Fundamentos UAS como Golden Course;
- una vertical slice V0.1 antes de ampliar funcionalidades.

Este modelo convierte esas decisiones de producto en contratos de dominio implementables.

## Impacto

### UX

El usuario podrá diferenciar:

- contenido trabajado;
- conocimiento comprendido;
- conocimiento dominado;
- temas que necesitan refuerzo.

El Dashboard podrá explicar por qué recomienda una acción.

### Datos

Se añaden IDs estables para conceptos, habilidades, objetivos y evidencias.

Los datos personales de progreso/evidencia permanecen fuera del contenido Markdown/MDX.

### Arquitectura

No cambia el stack aprobado.

El motor de aprendizaje vive en la capa de dominio y no depende directamente de Supabase, OpenAI ni de la UI.

### Contenido

Cada Topic podrá declarar conceptos, habilidades, objetivos y relaciones mediante IDs estables.

### Pruebas

Se requieren pruebas unitarias para:

- cálculo de mastery;
- estados derivados;
- ranking de recomendaciones;
- integridad de IDs y relaciones.

## Invariantes

1. Cambiar un título visible no cambia un ID estable.
2. Leer un Topic nunca equivale por sí solo a dominarlo.
3. Toda recomendación debe tener un motivo legible.
4. El motor funciona sin IA.
5. El motor funciona sin cloud.
6. El contenido académico y la evidencia personal se almacenan por separado.
7. V0.1 no introduce ML.
8. La definición de `Mastered` se especifica ahora, aunque puede no ser alcanzable hasta que exista evidencia de repaso en V0.2.

## No incluido en esta decisión

- fórmula definitiva de mastery;
- FSRS completo;
- sincronización multi-dispositivo;
- AI Tutor;
- simuladores avanzados;
- rediseño visual de la aplicación.
